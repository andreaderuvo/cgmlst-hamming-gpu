Exact cgMLST allelic distances on the GPU

A bioinformatics tool for bacterial genomic epidemiology: the full pairwise Hamming matrix between cgMLST allelic profiles, computed with the 1-bit AND + popcount tensor cores built for binarized neural networks. No training, no approximation.

The problem

In cgMLST each isolate is a profile of allele numbers, one per locus (≈ 1 000–5 000 loci). The distance between two isolates is the number of loci where both alleles are called and differ; missing calls are ignored. This matrix underlies outbreak clustering, minimum spanning trees and nearest-neighbour searches. Its cost grows with the square of the number of isolates, so for whole databases (tens to hundreds of thousands of profiles) it becomes the slow step.

The idea

Per locus, with 0 = missing:

[a≠0][b≠0][a≠b]  =  [a≠0][b≠0]  −  [a=b≠0]

Summed over loci, the distance matrix is a difference of two counts:

H = C − E
C = loci called in both           = P·Pᵀ      P: presence bits
E = loci called in both and equal = O·Oᵀ + R  O: one-hot bits of alleles seen ≥ τ times
                                              R: equal pairs of rarer alleles

Both P·Pᵀ and O·Oᵀ are products of binary matrices — exactly what 1-bit tensor cores compute, with int32 accumulation. The second product subtracts itself from the first in its epilogue.

Equality between many categories needs a one-hot expansion, and real data have a long tail of rare alleles that would make it huge. So only alleles seen at least τ times enter the one-hot; equal pairs among the rare ones are few, are enumerated exactly and subtracted on the GPU. τ only moves work between the two terms and is chosen automatically from a cost model under the free VRAM.

Only the upper triangle is computed, in row stripes on two CUDA streams: while the host formats one stripe, the next one is computed and copied back.

Why it is always exact

  1. The identity above holds for every pair of integers.
  2. For one locus, Σv [a=v][b=v] = [a=b]; frequent and rare alleles partition the alleles, so O·Oᵀ + R counts every equal called pair exactly once, whatever τ is.
  3. Everything is integer: bits, popcounts, int32 accumulators, u16 distances (≤ number of loci); zero padding adds nothing.
  4. Allele ids are renumbered per locus by an injective map that keeps 0 = missing, so hashed 32/64-bit ids work unchanged.

The repository ships a check that compares every cell with a brute-force count on inputs with missing, empty, INF-, non-numeric and hashed calls, across τ, stripe sizes and output layouts.

Results

NVIDIA L4 shared with other jobs (≈ 1.3–1.8 GB of VRAM free), 80-core CPU. Campylobacter, 63 005 real profiles × 1 142 loci.

Limit

The frequent-allele one-hot must fit in VRAM (no K-tiling yet). Real data with a long tail of rare alleles fit easily; a synthetic 50 000 × 5 000 set with 50 frequent alleles per locus (221 k one-hot columns ≈ 1.4 GB) does not fit on the shared GPU, though it would on a free 24 GB card.

Use it

git clone https://github.com/andreaderuvo/cgmlst-hamming-gpu && cd cgmlst-hamming-gpu
git clone --depth 1 https://github.com/NVIDIA/cutlass.git tensorcore/third_party/cutlass
cd tensorcore/rs && cargo build --release
./target/release/cgmlst-hamming-gpu -i calls.tsv -o dists.tsv
python3 check.py        # exactness check

Needs an NVIDIA GPU with tensor cores (sm_80 or newer; developed on sm_89), the CUDA toolkit and Rust. Input is an allele-call TSV (chewBBACA style). Options cover matrix layout (full / lower / upper), separators, missing character, locus and sample completeness filters, a distance cap and gzip output — see the README.

What is and isn't new

The pieces are known. One-hot × one-hot = match count is textbook. The frequent/rare split is the heavy/light technique for join-project queries (Amossen & Pagh, ICDT 2009; Deep, Hu & Koutris, SIGMOD 2020). Binary tensor cores have been used in genomics for epistasis on biallelic SNPs (Nobre et al.), and XOR+popcount Hamming on bit-packed genotypes is classic (PLINK 1.9). The contribution here is the combination: exact multi-allelic Hamming with missing data on 1-bit tensor cores, with the split as the cost knob.

It started as an attempt to write the distance as a hand-wired ReLU network. That works and is exact, but costs ≈ 11 operations per locus pair against 3 for a plain comparison, so it was dropped. Notes in RELU.md.
